# Engine baseline against the default patch

## Outcome

Over a holdout of synthesized reference clips (seeded `PatchbackSynthesized` references with their
known note sequences, generated by Patchback's synth), the fit's median normalized audio loss is
compared with the default patch's, and the benchmark records whether the go/no-go target was met,
with wall-clock time, render evaluations and listening examples. The Milestone A holdout is this
set of synthesized reference clips, not a dataset split: the dataset domain arrives in Milestone B,
and Milestone A does not wait on it (approval-record:engine-baseline-holdout).

## DESIGN.md

§ 9.2 (benchmark against the default), § 12.2 (sound matching gate), § 13 Milestone A, § 15.

## Acceptance

- spec/scenarios/engine-baseline-target-met.yaml
- spec/scenarios/engine-baseline-target-not-met.yaml

## Numeric obligations

- Reduction = (median default loss − median fit loss) / median default loss; Met at ≥ 20 %
  (§ 12.2). Met/NotMet is the go/no-go for Milestone B; Milestone A exits on a reduction > 0
  (epic:sound-engine Exit).
- Fixed sample rate, build and device configuration across compared runs (§ 12.2).

## Scope

- `crates/patchback-fit` (inferred: § 4.1 names no benchmark crate; the benchmark runs the fit
  against the default patch, and `patchback-fit` holds candidate search and audio loss).

## Open questions

- The specification still models the holdout as a dataset split: `spec/domains/fit.yaml`

  acceptance scenarios pass `holdout_split_id`. The spec owner remodels `Benchmark.holdout` as a
  set of synthesized reference clips; this story is not proposed until that lands.
- How many reference clips the holdout holds, and their seed.
